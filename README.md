# UK Pump Price Analytics

An interactive dashboard analysing eight years of UK weekly road fuel prices (Jan 2018 – Aug 2026), comparing them against the global Brent crude benchmark and cross-referencing the biggest price swings against real, sourced world events (COVID-19, the Russia-Ukraine war, the 2026 Iran/Strait of Hormuz conflict, OPEC+ decisions, and UK fuel duty changes).

Built as a portfolio project to demonstrate data cleaning, pipeline design, statistical analysis, API design, and frontend data visualisation — not intended as financial advice.

## Why this project

Retail fuel prices sit at the intersection of global commodity markets, currency movements, tax policy, and geopolitics. This project asks: **can we trace UK pump prices back to real, verifiable causes, and be honest about where we can't?**

Rather than just plotting a CSV, the project:
- Cleans and merges two real datasets of different frequencies (weekly UK pump prices, monthly global Brent crude)
- Statistically detects "spikes" (weekly price moves that are outliers, not just big numbers) using a z-score threshold
- Cross-references those spikes against a researched, source-linked events dataset
- Is explicit in the UI about the difference between correlation and causation
- Features an interactive dashboard with Chart.js visualizations, event filtering, and expandable analysis sections

## Data sources

| Data | Source | Frequency | Coverage |
|---|---|---|---|
| UK ULSP/ULSD pump prices, duty, VAT | [gov.uk weekly road fuel prices](https://www.gov.uk/government/statistics/weekly-road-fuel-prices) | Weekly | Jan 2018 – Aug 2026 |
| Brent crude spot price (USD/bbl) | [FRED / US EIA, series MCOILBRENTEU](https://fred.stlouisfed.org/series/MCOILBRENTEU) | Monthly | Jan 2018 – Aug 2026 |
| World events | Researched and cited individually — see `data/events.json` | — | — |

Brent and pump prices are on different frequencies (monthly vs weekly), so each weekly row is matched to the most recent Brent reading using a backward `merge_asof` join — a standard, defensible way to compare series without inventing data points.

`backend/fetch_brent.py` can refresh the Brent series from FRED's public CSV endpoint (no API key required) if you want to pull a fresh copy rather than use the committed snapshot in `data/raw/`.

## Architecture

```
fuel-price-analytics/
├── data/
│   ├── raw/                     # source CSVs, untouched
│   ├── processed/                # generated by the pipeline (gitignored)
│   └── events.json               # researched, source-linked event dataset
├── backend/
│   ├── data_pipeline.py          # cleaning, derived metrics, spike detection, event matching
│   ├── fetch_brent.py            # optional: refresh Brent data from FRED
│   └── app.py                    # Flask app + REST API
├── frontend/
│   ├── templates/index.html
│   └── static/{css,js}/          # vanilla JS + Chart.js, no build step
├── tests/
│   └── test_data_pipeline.py     # pytest unit tests
└── run.py                        # entry point
```

**Design choices worth noting:**
- Spike detection uses a **z-score threshold** on weekly % change, not a fixed pence cutoff, so it stays meaningful whether prices are around 120p or 190p.
- The data pipeline is a set of pure functions operating on DataFrames, kept separate from the Flask layer, so it's independently testable (see `tests/`).
- The Flask app loads and processes data once at startup rather than on every request — the dataset is small enough to comfortably fit in memory.
- The frontend intentionally has **no build step** (no npm/webpack/React) — it's vanilla JS + Chart.js served directly by Flask, which keeps the whole thing runnable with just `pip install` and one command.
- **Dashboard features**: Interactive Chart.js visualizations with event annotations, rise/fall filtering for price movements, expandable summary and events sections, and a modern color scheme optimized for readability.

## Running it locally

```bash
git clone (https://github.com/tagzzz0/fuel-price-analytics.git)
cd fuel-price-analytics
pip install -r requirements.txt

# optional: refresh Brent crude data from FRED (a snapshot is already committed)
python backend/fetch_brent.py

python run.py
```

Then open **http://127.0.0.1:8000** (note: port 8000 is used to avoid conflicts with macOS AirPlay Receiver on port 5000).

## Running the tests

```bash
pytest tests/ -v
```

## API reference

| Endpoint | Description |
|---|---|
| `GET /api/prices?fuel=petrol&start=YYYY-MM-DD&end=YYYY-MM-DD` | Weekly price, % change, rolling averages, tax split, spike flag, and matched Brent crude reading |
| `GET /api/summary` | Headline stats (latest, all-time high/low, % change since 2018) per fuel |
| `GET /api/spikes?fuel=petrol&top=20` | The biggest statistically significant weekly moves, with matched events |
| `GET /api/events` | The full researched events dataset |

## Honest limitations

- **Correlation, not causation.** The dashboard flags that a price move and a world event happened in the same window — it does not claim the event *caused* the move. Multiple factors (crude price, GBP/USD exchange rate, OPEC+ policy, UK duty changes) often move together, and the summary text says so explicitly.
- **Brent is monthly, pump prices are weekly.** The overlay carries the last known monthly Brent reading forward across each week, which smooths out any within-month crude volatility.
- **The events list is not exhaustive.** It covers the clearest, best-documented drivers of the largest moves in this dataset (all individually sourced in `data/events.json`) rather than every possible contributing factor.

## Possible extensions

- Add UK CPI/RPI to show fuel price changes in real terms
- Add GBP/USD exchange rate as a third comparison series
